1. Quick start

The whole flow, three steps:
  1. Get parts into the tray. Either drop Import .moz(s)… from Mozaik (full drill + band data), paste a text order via Import parts…, or hit Load sample list in the import modal.
  2. Place them on the pallet. Tap a tray row to arm it, tap the pallet to drop it. Or let Suggest layer pack a layer for you, or Build stack do the whole stack in a search.
  3. Save. Type a SKU in the top bar (e.g. QBZ-WHITE), hit Save recipe. If your device is provisioned it syncs to the cloud so every device sees it. Open the Stacker Guide from Library → 🎯 Guide for the shop-floor view.

2. The header (left → right)

  • ‹ Bedrock — go back to the main PWA.
  • Stacking Recipe Editor · v3.x — version pill; the number tells you what's live.
  • SKU input — the name this recipe saves under. Required to Save.
  • sig … — geometry fingerprint of the current tray. Two orders with the same parts get the same signature (order-independent). Used to match orders to recipes.
  • Import parts… / Import .moz… / Match text… / Match .moz… — load parts or find matching recipes (see §3, §4).
  • Library… — browse saved recipes (see §10).
  • Save recipe — writes the current state under the SKU.
  • Export… — CSV / JSON / PDF / Mozaik files / Mozaik job zip (see §11).
  • ? — this guide.

3. Importing parts

Four ways to fill the tray:
  • Import parts… — text-import modal. Paste rows in the format partNum   name   qty   L_in   L_mm   W_in   W_mm (tab-separated). Section headers like Outer Fascia group the rows. The modal has a Load sample list button to see the shape.
  • Import .moz… — pick one or more Mozaik .moz files. Reads part identity, dimensions, quantity, plus the full drill/band record (needed for the Drill editor and Mozaik export round-trip).
  • Match text… / Match .moz… — see §4. Also imports parts as a side-effect.

What .moz gives you that text doesn't: per-part drilling operations (face holes, edge bores, line-bore rows), edge-band flags, part type. You can only edit drills on parts that came from a .moz.

4. Matching an order to a saved recipe

Both Match text… and Match .moz… compute the signature of what you're feeding in, then search the Library (local + cloud) for recipes with the same signature.
  • Match text… — paste an order; if a recipe matches, offers to Load it (or Remap part numbers to this order's).
  • Match .moz… — the important one. Given the same match, offers three options:
    1. Load V1 — open the existing recipe.
    2. Fork as V2 — copy the existing layout to a new SKU (auto-suggests QBZ-WHITE → QBZ-WHITE V2, or bumps V3 → V4). Change one thing and Save without touching V1.
    3. New blank — throw away the match, start from empty.

5. Placing parts on the pallet

Click a part row in the tray → it arms. Click on the pallet → it drops on the active layer. Repeat.
  • Press R before you drop to pre-rotate the armed part 90° (Shift+R = −90°). Rotation is remembered until you disarm.
  • Drag placed parts to move them. They snap to the footprint walls and to each other.
  • Snap checkbox turns snapping on/off. Gap field sets a kerf/gap in mm that separates snapping parts.
  • Keep in bounds — parts can't leave the footprint while it's on.
  • Two parts overlapping within one layer turn red (a real collision). Overlaps between layers are fine — that's the stack.
  • Ghost below checkbox draws the previous layer faintly under the current one, so you can align stacks.
  • Labels checkbox toggles the part# text drawn on each placed part.
  • Grid dropdown snaps positions to a grid (5/10/25/50 mm or 0.5/1/2 in).

6. Layers panel

Right column, LAYERS. Each row is one horizontal layer in the pallet stack.
  • Click L1 / L2 / … to switch the active layer.
  • + Layer — add a new empty layer on top.
  • Duplicate — copy the active layer's placement.
  • Clear stack — wipe every placement (keeps the tray).
  • Per-layer controls: ↑/↓ reorder, Copy, Clear, Delete.
The panel also shows Parts placed / Layers / Stack height / Active-layer fill / Support (%). Support flags severe issues (a part sitting on <70% support from below).

7. Auto-stacking

Two levels of automation:
  • Suggest layer — packs one layer densely. Try both orientations per part, backfills leftover space, leaves what didn't fit in the tray. Click again to fill the next layer.
  • Build stack — runs a nesting search across many part orderings + carton placements. Effort selector (Fast / Balanced / Thorough) trades time for quality. Returns three distinct layouts to flip between; big panels go low, small parts high.
  • Big parts first checkbox biases the search toward large panels on lower layers.
  • Same SKU at the same effort reproduces the same result — it's deterministic.

8. Cartons

Cartons are frame-boxes stacked in the void reserved by Build stack across the top layers.
  • Define a carton by Name / L / W / H in the Cartons pane. A 100mm-tall carton spans ~6 layers of 19mm panels.
  • Auto-stacking reserves the void; you set the actual carton into place by hand.
  • Cartons render dashed on the pallet, distinct from parts.

9. Drill / band editor (ⓘ button)

Every part row in the tray has a small ⓘ button. Tap it to open a per-part detail modal with:
  • Identity — part #, name, section, dims, type, source layer.
  • Bands — four checkboxes (Front/Y0, Back/YW, Left/X0, Right/XL). Toggle any edge on/off.
  • Operations — editable table of drilling ops. Every X/Y/Ø/depth/axis-h/flip/qty cell is an input. Rules mirror Mozaik: X locked on X0/XL edges, Y locked on Y0/YW edges, Axis-h + Flip only where meaningful, Qty only on line-bores.
  • + Face hole — add a face-drilled hole at default position (34, 36) with 5mm Ø × 15mm depth.
  • + Edge bore — add a horizontal edge bore on the X0 edge.
  • + Line bore row — add a 5-dot line-bore row at 32mm spacing.
  • ✕ per row — delete an op.
  • Live SVG preview redraws after every change. Green segments = banded edges. Solid dots = near-face holes. Red dashed = flip-side. Amber ticks = edge bores. Blue dots = line-bore.
Edits auto-save to the recipe. Hit Save on the header to persist to the cloud; Mozaik files / Mozaik job zip exports carry the edits verbatim.
Parts imported from text have no .moz drill data — the modal shows a "re-import .moz to view drills" message.

10. Save + Library + cross-device sync

Save recipe writes the current state under the SKU in the top bar. Requires a SKU (input flashes red if empty). Overwrite prompt if the SKU already exists.

Cross-device sync: when your device is provisioned, Save writes to Supabase too. Library shows every recipe on every provisioned device, badged:

  • Local + Cloud rev N — saved here AND in the cloud.
  • Local only — only on this device.
  • Cloud only — on another device, not this one yet. Tap Load to fetch.

Delete in the Library shows a two-step dialog when a cloud copy exists: "Delete BOTH local AND cloud" (permanent, every device loses it) OR "Delete LOCAL only" (cloud copy stays).

To provision a device for cloud sync: get the setup URL from Zac and open it once — you'll see a toast "✓ Device provisioned for Bedrock sync". After that this device reads + writes the cloud library automatically.

Diagnostic: in DevTools console, run stackingDiag() — dumps provisioning + cloud reachability + local recipe count.

11. Exports

Export… opens six options:
  • CSV — per-part placement (layer, partNum, X/Y, angle, dims). Includes cartons.
  • JSON — full snapshot (same data + footprint/pallet/settings). Machine-readable.
  • PDF — colour — cover + all-layers overview + one page per layer. Shareable.
  • PDF — B&W — same PDF, flattened for cheaper printing.
  • Copy CSV — clipboard, no download.
  • Mozaik files (per-layer .moz) — one .moz per stacking layer. Feed them into Mozaik individually.
  • Mozaik job zip — full Mozaik job structure: Room1 + N layer .moz + JobDat + JobParms. Unzip into your Mozaik Jobs folder and open the job.
Mozaik exports carry any drill/band edits you made in the ⓘ editor.

12. Stacker Guide (guide.html)

Full-screen shop-floor view for the iPad or TV next to the stacking station. Big dark UI, giant tap-targets, no glare.
  • Open from the Recipe Editor — Library → any recipe row has a 🎯 Guide button.
  • Direct URL — guide.html?sku=YOUR-SKU.
  • Tied to an order — guide.html?order=32748 looks up the assigned recipe from Supabase. If none is assigned, shows a picker to pick one; the pick saves back to the order so any device opens the same recipe next time. Progress keys under order_number, so two orders sharing a recipe track separately.
  • Auto-assign shortcut — guide.html?order=N&sku=X assigns + loads in one round-trip. Good for QR codes or Bedrock deep-links.
  • Bedrock integration — the Inspect Order modal has a green "🎯 Stacker Guide" button that opens the guide for that order.
In the guide itself:
  • Tap each part on the layer → turns green with a ✓, in-place counter increments.
  • Progress persists to localStorage per SKU (or per order). If the iPad reloads mid-stack, tap-marks resume — you'll see "resumed N in-place" in the toast.
  • ← Prev / Layer Complete → / Next Layer → at the bottom. Complete auto-advances after 800ms.
  • Reset button clears all tap marks + returns to Layer 1.
  • If you re-save the recipe with a different layout, guide progress for that SKU auto-clears (stale marks would point at wrong parts).

13. Tray sort + search

Above the parts list:
  • Filter parts… — search box, matches partNum + name (case-insensitive).
  • Sort dropdown — Section (default) keeps the grouped/collapsible layout. Any other choice (Length ↓/↑, Width ↓/↑, Qty ↓/↑, Name, Part #) flattens to one list sorted by that key. Swatch color still identifies each part's source section.
  • Collapse all / Expand all — Section view only.
Your sort choice persists per-device across recipes.

14. On a phone or tablet

Pinch to zoom, drag one finger on empty space to pan, tap Fit to reset the view. Tap a part to select it — the bar at the bottom nudges, rotates, duplicates, or deletes it. Use the tabs under the canvas to reach Parts, Selection, Layers, Cartons, and Settings. Header wraps to two rows on narrow screens so every button stays reachable.

15. Coordinate model

Coordinates are distances from the chosen origin corner of the chosen datum (footprint or pallet), measured inward, so values are always positive. X runs along the long side, Y along the short side. Angle is the part rotation in degrees. The Reference setting picks whether an exported part position points at the center or one of the corners. Export carries the reference point you pick plus the center, angle, and L×W, so it can be re-mapped to whatever downstream tool expects.

17. Troubleshooting

  • Saved a recipe but not in Library — check the toast. Missing SKU flashes the input red; overwrite-cancel says "Save cancelled". Every successful save toasts ✓ Saved SKU …. If you're on mobile and see nothing, quit and reopen the browser (cache) and reload with ?cachebust=1.
  • Guide says "Recipe not found" — the SKU in the URL doesn't match any local or cloud recipe. Open the Editor, check Library for the exact spelling.
  • Cloud sync says "OFF" — this device isn't provisioned. Get the setup URL from Zac and open it once.
  • Drill editor says "no .moz drill data" — this recipe was authored from text-paste, not .moz. Re-import the source .moz file(s) via Import .moz… to get drills + bands.
  • Save button did nothing (mobile) — check the version pill in the header. If below 3.11, browser is serving cached HTML — quit Safari, reopen, load with ?cachebust=1.
  • Diagnostic dump — open DevTools console (Chrome ⌘⌥J), run stackingDiag(). Prints provisioning state + cloud reachability + local recipe count. Paste that to Zac.
  • Debug mode — append ?debug=1 to the URL. A pinned green log at the bottom of the screen records every tap and toast — useful when a button seems to do nothing on mobile.
